# 第3回 SBOMとライセンス，証跡の保管

この回では，出荷する依存関係の一覧(SBOM)を作り，そのライセンスを検査するゲートを作る．
あわせて，これまでのゲートが残した証跡を集め，消せない形で保管する場所を作る．

## 3-1 準備

1. 題材の検査が通ることを確かめる．

   ```console
   cd app
   mise run check
   ```

2. この回の問題を当て，コミットする．

   ```console
   mise run iteration:start 3
   mise run install
   git add -A
   git commit -m "メモの本文をリッチテキストで書けるようにする"
   ```

3. `mise run dev:web`で画面を開き，メモの入力欄がリッチテキストエディタになったことを確かめる．
   `node_modules/tinymce/package.json`の`license`も見ておく．

## 3-2 学ぶこと

### SBOM

SBOM(Software Bill of Materials)は，ソフトウェアに含まれる部品(依存関係)の一覧である．
部品ごとに，名前，版，ライセンス，パッケージの識別子(purl)を持つ．
新しい脆弱性が公開されたとき，SBOMがあれば，その部品を使っているかをすぐに調べられる．
顧客から提出を求められることも増えている．

形式は，CycloneDXとSPDXが広く使われる．
この講座では，Trivyが作るCycloneDXのJSONを使う．

```console
trivy fs --format cyclonedx --output web.cdx.json .
```

pnpmのロックファイルからは，出荷する依存関係(`devDependencies`を除く)が部品になる．
ライセンスは，`node_modules`の中の`package.json`から読む．
Goのモジュールのライセンスは，モジュールのキャッシュから読む．

規格や手引は次のことを求める．

- NIST SSDF PS.3：出荷するソフトウェアの部品を記録し，保管する．
- 経済産業省「ソフトウェア管理に向けたSBOMの導入に関する手引」：SBOMの作り方と使い方を示す．

### ライセンスの検査

オープンソースのライセンスには，使う側に義務を課すものがある．
GPLのようなコピーレフトのライセンスでは，組み合わせたソフトウェアを配るとき，ソースコードの開示を求められることがある．
SaaSでも，ブラウザに配るJavaScriptは「配布」に当たる．

仕組みとしては，許可するライセンスの一覧を決め，それ以外を止める．
許可の一覧は方針なので，基準値として`ops/standards.yaml`に書く．
一覧にないライセンスは，法務の確認を経て一覧に足す．

### 証跡を消せない形で保管する

監査では，ある期間の証跡を求められる．
CIのartifactは90日程度で消えるので，別の場所に保管する．
保管した証跡を後から書き換えられると，証跡として信用できない．

S3のObject Lockは，保管期間の間，オブジェクトを消したり上書きしたりできなくする．
COMPLIANCEモードでは，管理者も消せない．
Object Lockを使うには，バケットの版の管理(versioning)を有効にする．

```hcl
resource "aws_s3_bucket_object_lock_configuration" "example" {
  bucket = aws_s3_bucket.example.id
  rule {
    default_retention {
      mode = "COMPLIANCE"
      days = 400
    }
  }
}
```

OpenTofuでは，`yamldecode(file(...))`でYAMLを読める．
保管期間を基準値から読めば，日数を書く場所は1つで済む．

### CIのジョブの間で証跡を渡す

`actions/download-artifact`の`pattern`と`merge-multiple: true`で，ほかのジョブが残したartifactを1つの場所に集められる．
`needs`で先に終わるべきジョブを指定し，`if: always()`でそれらが失敗したときも動かす．

`services`でコンテナを起動すると，ジョブの間だけ使える．
この講座では，MiniStackを起動して証跡の保管場所を作り，送る仕組みが動くことを確かめる．

## 3-3 テストリスト

次の要求を満たすテストのリストを，`TESTLIST.md`に書く．
ゲートのテストと運用テストを分けて書く．

### 要求

- `mise run sbom`は，Webの画面とAPIのそれぞれのSBOMを`out/evidence/sbom/`に作る．
- `mise run gate:license`は，許可していないライセンスの部品や，ライセンスの分からない部品がSBOMにあれば失敗する．
  部品とライセンスを表示する．
- 証跡の保管場所は，基準値の日数だけ消せない設定である．
- 保管した証跡は，版を指定しても消せない．
- `mise run evidence:upload`は，`out/evidence/`を日付とコミットごとの場所へ送る．

### 使用例

```console
$ mise run gate:license
license: 2 SBOMs, all allowed
```

### 作るもの

- `tools/gates/license.ts`：SBOMのファイルを引数で受け取る．
- `infra/evidence.tf`と，バケットの名前の出力．
- `mise.toml`の`sbom`，`gate:license`，`test:ops`，`evidence:upload`タスク．

ゲートのテストの入力には，部品を2つだけ書いた小さなSBOMを使う．
運用テストは`tests/ops/`に置き，`mise run up`で作った環境に対して実行する．

既存のテストへの影響も考える．

## 3-4 設計書

- `ops/standards.yaml`：許可するライセンスの一覧と，証跡の保管期間を足す．
- `ops/items.yaml`：SBOMの作成，ライセンスの検査，証跡の保管の3つを足す．
  証跡の保管の仕組みは，証跡を集めて送る`evidence`ジョブである．
- `ops/policy.md`：証跡の保管場所，置き場所の決まり，保管期間を書く．

## 3-5 テスト駆動の実装

### gate:license

SBOMの`components`を順に見る．
ロックファイル(`type`が`application`)と，版を持たない自分たちのモジュールは外す．
ライセンスは，`licenses[].license.id`か`licenses[].expression`にある．

題材に対して実行すると，仕込まれたエディタが見つかる．

```text
[gate:license] $ pnpm exec tsx tools/gates/license.ts "${EVIDENCE_DIR:-out/evidence}"/sbom/*.cdx.json
out/evidence/sbom/web.cdx.json: tinymce@7.9.3: GPL-2.0-or-later は許可されていない
[gate:license] ERROR task failed
```

ライセンスの問題は，例外にしないで直す．
この回では，エディタを外してテキストの入力欄に戻す．

```console
pnpm --filter @app/web remove tinymce
```

### 証跡の保管場所

1. `infra/evidence.tf`にバケット，版の管理，Object Lock，ライフサイクルを書く．
2. 本番の環境への適用の前に，変更を確かめる．

   ```console
   tofu -chdir=infra plan
   mise run up
   ```

3. 運用テストを書いて実行する．
   バケットの名前は，`tofu -chdir=infra output -raw evidence_bucket`で得られる．
   AWS CLIの`aws s3api get-object-lock-configuration`と`aws s3api delete-object --version-id`を使う．

   ```console
   mise run test:ops
   ```

4. 証跡を送り，一覧する．

   ```console
   mise run evidence:upload
   aws s3 ls --recursive s3://app-evidence/
   ```

保管した証跡は消せないので，`mise run down`も失敗するようになる．
環境を初めからやり直すときは，MiniStackのデータのボリュームごと消す．

### CI

1. `sbom`ジョブで`gate:license`を実行し，`out/evidence/`をartifactに残す．
2. これまでのジョブも，`out/evidence/`全体を残す形にそろえる．
3. `evidence`ジョブで，MiniStackを起動し，artifactを集める．
   続けて`mise run up`，`mise run test:ops`，`mise run evidence:upload`を実行する．
   GitHubのランナーは`000000000000.localhost`を名前解決できないので，先に`/etc/hosts`へ足す．
